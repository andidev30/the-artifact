# ee/

Code under `LICENSE-EE` at the repository root (source-available, not AGPL), as in GitLab EE. Everything outside an `ee/` folder is AGPL-3.0.

- Belongs here, kind 1, hosted only: anything that only makes sense when `SELF_HOSTED=false` (marketing site, pricing, contact sales, the hosted onboarding welcome, issuing license keys, and later billing and plans). Gate it on `SELF_HOSTED` and add a test that it is off on a self-hosted install.
- Belongs here, kind 2, enterprise features (audit log, version retention, SSO, SCIM): code a self-hosted install runs only with a valid license key. Gate every entry on `hasEnterprise()` or `requireEnterprise` from `apps/api/src/license.ts`; in the web app, hide it unless the API says it is on, and add a test that it is off without a license, after the grace period, and on the hosted service. Turning off never deletes data.
- Doesn't belong here: anything a self-hosted install needs without a license, including checking license keys (`apps/api/src/license.ts` is core). When in doubt it is core.
- Core may reference `ee/` only at its entry points (see the list below). `ee/` may import core freely.

Entry points in the web app: `pages/Home.tsx` lazy-loads `Landing`, `ContactSales` and `Legal` only when the install is not self-hosted, so their code and CSS (`Landing.css`) never load there; `pages/Onboarding.tsx` shows `Welcome` on the hosted service only, and core pages hide the ways to create an organization when `/api/config` says `newOrganizations: false`, which `ee/plans.ts` decides; `pages/Admin.tsx` lazy-loads `IssueLicenses` (issuing license keys) on the hosted service only; `pages/Auth.tsx` links sign-up to the terms and privacy policy on the hosted service only; `HostedInsights` in `pages/Home.tsx`, rendered by `main.tsx`, lazy-loads `Insights` (Vercel Web Analytics and Speed Insights) on the hosted service only, and `insightsUrl.ts` strips secrets from every address they send. A new route with a token, a secret slug or a sensitive query in its path must be added there. `pages/OrganizationSettings.tsx` shows `RetentionSection` to owners and admins on a self-hosted install; it stays visible without a license, disabled, to say why the policy isn't applied.

## Legal pages

`Legal.tsx` renders the Markdown in `legal/` at `/legal/<slug>`: `terms`, `privacy`, `subprocessors` and `dpa` (listed in `LegalFooter.tsx`, which the landing footer also uses). `{{APP_URL}}` is replaced with the service's address. They describe what the hosted service really does with data, so keep them true when that changes: a new table or column with personal data, a new cookie, a new email, a new provider (add it to `subprocessors.md` before it goes live), a new log field, or a changed retention period. Change "Last updated" when the text changes.
