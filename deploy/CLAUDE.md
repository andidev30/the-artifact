# deploy/

Self-hosting manifests. Operators follow `docs/self-hosting.md` (Compose) and `docs/kubernetes.md` (Helm and the plain manifests), so any change here needs the matching doc change. The repo-root `docker-compose.yml` is for development only.

- `docker-compose/` — app + Postgres + MinIO. `app.env` holds the app's settings; `.env` holds what Compose itself reads (`ARTIFACT_VERSION`, port, passwords, `S3_*`). The app runs the published `ghcr.io/andidev30/the-artifact` at `ARTIFACT_VERSION`; `docker-compose.build.yml` is the opt-in override (turned on with `COMPOSE_FILE` in `.env`) that builds from the checkout as `the-artifact:local`. The release PR bumps the `ARTIFACT_VERSION` default in `docker-compose.yml` and `.env.example`, and `newTag` in `kubernetes/kustomization.yaml`, through their `x-release-please` markers (listed under `extra-files` in `release-please-config.json`); keep the markers on those lines. The project `name: the-artifact` is kept so installs that moved here from the repo root keep their volumes; don't rename it or the volumes.
- `kubernetes/` — Kustomize base (`kubectl apply -k deploy/kubernetes`). Every setting goes into one Secret generated from `app.env`. `patches/thumbnails-off.yaml` is for clusters that can't install the seccomp profile.
- `helm/the-artifact/` — the Helm chart, published to `oci://ghcr.io/andidev30/charts/the-artifact` by the Release workflow after the image. It mirrors `kubernetes/`: same env vars, probes, seccomp profile (`thumbnails.enabled`), `Recreate` with one replica and no replica value (the app migrates on start), plus its own Postgres and MinIO StatefulSets (not Bitnami subcharts) whose generated passwords are kept through `lookup` and `helm.sh/resource-policy: keep`. A new setting operators need gets a value in `values.yaml`, `values.schema.json` and the `the-artifact.env` helper in `templates/_helpers.tpl`, and a row in the Helm table in `docs/kubernetes.md`. `version` and `appVersion` in `Chart.yaml` carry `x-release-please-version` markers; `release-please-config.json` lists it with `"type": "generic"`, because a plain `.yaml` entry also runs release-please's YAML updater, which rewrites `version` through js-yaml and drops every comment, markers included. `ci/*-values.yaml` are the combinations `.github/workflows/helm.yml` lints, renders and validates with kubeconform; that workflow also installs the chart into kind with thumbnails on. Check a change with `helm lint deploy/helm/the-artifact` and `helm template`.
- `seccomp-chromium.json` — Docker's default seccomp profile plus the namespace calls Chromium's sandbox needs for thumbnails of untrusted pages. Used by every setup; don't replace it with `unconfined` or turn the Chromium sandbox off.

When a setting is added or changed in `apps/api/src/env.ts`, update the `*.env.example` files here if operators are expected to set it, and `docs/configuration.md` either way. Only `.example` files are committed; real `.env`/`app.env` files are ignored by the `.gitignore` in each folder.
